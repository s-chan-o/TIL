# 정렬 관련

## 주요 정렬 알고리즘의 시간복잡도 비교

정렬 알고리즘은 데이터를 특정 기준에 따라 순서대로 배치하는 알고리즘이다.  
알고리즘마다 시간복잡도와 특징이 다르기 때문에 데이터 크기와 상황에 맞게 선택해야 한다.

### 시간복잡도 비교

| 정렬 알고리즘 | 평균 시간복잡도 | 최악 시간복잡도 | 공간복잡도 | 특징 |
|---|---:|---:|---:|---|
| 버블 정렬 | O(n²) | O(n²) | O(1) | 인접한 값을 비교하며 교환 |
| 선택 정렬 | O(n²) | O(n²) | O(1) | 가장 작은 값을 찾아 앞으로 보냄 |
| 삽입 정렬 | O(n²) | O(n²) | O(1) | 거의 정렬된 데이터에 유리 |
| 병합 정렬 | O(n log n) | O(n log n) | O(n) | 안정적이지만 추가 메모리 필요 |
| 퀵 정렬 | O(n log n) | O(n²) | O(log n) | 평균적으로 빠르지만 피벗에 따라 최악 가능 |
| 힙 정렬 | O(n log n) | O(n log n) | O(1) | 추가 메모리가 적고 최악도 안정적 |

### 간단 정리

- **버블 정렬**: 구현은 쉽지만 성능이 좋지 않다.
- **선택 정렬**: 매번 최솟값을 찾아 정렬한다.
- **삽입 정렬**: 데이터가 거의 정렬되어 있으면 빠르다.
- **병합 정렬**: 항상 `O(n log n)`이지만 추가 메모리가 필요하다.
- **퀵 정렬**: 평균적으로 매우 빠르지만 최악의 경우 `O(n²)`이 될 수 있다.
- **힙 정렬**: 최악의 경우에도 `O(n log n)`을 보장한다.

### 정리

- 작은 데이터나 학습용으로는 버블, 선택, 삽입 정렬을 이해하면 된다.
- 일반적으로 효율적인 정렬은 병합 정렬, 퀵 정렬, 힙 정렬이다.
- 안정적인 시간복잡도가 중요하면 병합 정렬이나 힙 정렬이 유리하다.
- 평균 성능을 중시하면 퀵 정렬이 많이 사용된다.


## 퀵 정렬의 동작 원리와 최악의 경우

퀵 정렬은 **피벗(pivot)을 기준으로 데이터를 나누고, 나뉜 부분을 다시 정렬하는 분할 정복 알고리즘**이다.

### 동작 원리

퀵 정렬은 다음 순서로 동작한다.

```text
1. 배열에서 피벗을 하나 선택한다.
2. 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 나눈다.
3. 왼쪽 부분과 오른쪽 부분에 대해 같은 과정을 반복한다.
4. 더 이상 나눌 수 없으면 정렬이 완료된다.
```

예를 들어 다음 배열이 있다고 하자.

```text
[5, 3, 8, 4, 2]
```

피벗을 `5`로 잡으면 다음처럼 나눌 수 있다.

```text
[3, 4, 2]  5  [8]
```

이후 왼쪽 `[3, 4, 2]`와 오른쪽 `[8]`에 대해 다시 같은 과정을 반복한다.

### 시간복잡도

| 경우 | 시간복잡도 |
|---|---:|
| 평균 | O(n log n) |
| 최악 | O(n²) |

평균적으로는 피벗을 기준으로 데이터가 절반에 가깝게 나뉘기 때문에 `O(n log n)`이다.

```text
n개 -> n/2개 -> n/4개 -> ...
```

### 최악의 경우

퀵 정렬의 최악의 경우는 **피벗이 계속 최솟값이나 최댓값으로 선택되는 경우**이다.

예를 들어 이미 정렬된 배열에서 매번 첫 번째 값을 피벗으로 선택한다고 하자.

```text
[1, 2, 3, 4, 5]
```

첫 번째 값 `1`을 피벗으로 잡으면 왼쪽에는 아무것도 없고, 오른쪽에 나머지 값이 모두 몰린다.

```text
[]  1  [2, 3, 4, 5]
```

다음에도 `2`가 피벗이 되면 또 한쪽으로만 나뉜다.

```text
[]  2  [3, 4, 5]
```

이렇게 계속 한쪽으로 치우치면 분할이 거의 일어나지 않아 `O(n²)`이 된다.

### 정리

- 퀵 정렬은 피벗을 기준으로 작은 값과 큰 값을 나누는 정렬이다.
- 평균 시간복잡도는 `O(n log n)`이다.
- 피벗이 균형 있게 선택되면 빠르다.
- 피벗이 계속 최솟값이나 최댓값으로 선택되면 최악의 경우 `O(n²)`이 된다.
