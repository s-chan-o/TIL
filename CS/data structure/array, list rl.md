# 배열 & 리스트 관련

## 배열(Array)과 연결 리스트(Linked List)의 차이

**배열**

배열은 메모리에 연속된 공간에 데이터를 저장한다. -> 조회에 강함

**연결리스트**

각 노드가 데이터와 다음 노드의 포인터를 가지며 메모리 상 흩어져있다.
메모리에 연속으로 저장되지 않아도된다. -> 삽입/삭제에 강함

## 시간복잡도 비교

| 작업 | 배열(Array) | 연결 리스트(Linked List) |
|---|---:|---:|
| 접근(인덱스) | O(1) | O(n) |
| 탐색 | O(n) | O(n) |
| 삽입/삭제 (앞) | O(n) | O(1) |
| 삽입/삭제 (뒤) | O(1) | O(n) *(단, tail 포인터가 있으면 O(1))* |
| 삽입/삭제 (중간) | O(n) | O(n) *(탐색)* + O(1) *(삽입/삭제)* |

> 시간 복잡도 : 말 그대로 입력의 크기가 커질 때, 연산이 얼마나 늘어나는지를 나타내는거다. 예를 들어 데이터가 10개일때 1번 걸리는 작업이 데이터가 100개여도 거의 1번이면 O(1)이고, 데이터가 10개면 10번, 100개면 100번쯤 보면 O(n)이다.

**공간**

- 배열 -> 크기 고정(정적), 메모리 낭비 가능
- 연결 리스트 -> 동적 크기, 포인터 공간 추가 소모

**사용선택**

- 인덱스 접근이 잦고 크기가 고정 -> 배열
- 삽입/삭제가 잦고 크기가 변동 -> 연결리스트

## ArrayList와 LinkedList의 차이(Java 기준)

Java의 `ArrayList`와 `LinkedList`는 둘 다 `List` 인터페이스를 구현한 자료구조이다.  
겉으로는 비슷하게 사용할 수 있지만, 내부 구현 방식이 달라 성능 특성이 다르다.

### ArrayList

`ArrayList`는 내부적으로 배열(`Object[]`)을 사용한다.  
데이터가 메모리에 연속적으로 저장되기 때문에 인덱스로 바로 접근할 수 있다.

```java
List<String> list = new ArrayList<>();
list.add("A");
list.add("B");
list.add("C");

System.out.println(list.get(1)); // B
```

**특징**

- 인덱스 접근이 빠르다. → `O(1)`
- 마지막 위치에 추가하는 작업은 보통 빠르다. → 평균 `O(1)`
- 중간 삽입/삭제는 느릴 수 있다. → `O(n)`
- 중간에 값을 넣거나 지우면 뒤의 요소들을 밀거나 당겨야 한다.
- 배열 크기가 부족하면 더 큰 배열을 새로 만들고 기존 데이터를 복사한다.

### LinkedList

`LinkedList`는 내부적으로 노드(Node)를 연결한 구조이다.  
각 노드는 데이터와 이전/다음 노드의 참조를 가진다.

```text
A <-> B <-> C
```

Java의 `LinkedList`는 단일 연결 리스트가 아니라 **이중 연결 리스트**이다.

```java
List<String> list = new LinkedList<>();
list.add("A");
list.add("B");
list.add("C");

System.out.println(list.get(1)); // B
```

**특징**

- 인덱스 접근이 느리다. → `O(n)`
- 특정 위치를 찾으려면 앞 또는 뒤에서부터 노드를 따라가야 한다.
- 앞/뒤 삽입과 삭제가 빠르다. → `O(1)`
- 중간 삽입/삭제는 위치를 이미 알고 있으면 빠르다. → `O(1)`
- 하지만 그 위치를 찾는 탐색 비용이 보통 `O(n)`이다.
- 노드마다 이전/다음 참조를 저장해야 하므로 메모리를 더 사용한다.

### 시간복잡도 비교

| 작업 | ArrayList | LinkedList |
|---|---:|---:|
| 인덱스 접근 | O(1) | O(n) |
| 탐색 | O(n) | O(n) |
| 앞 삽입/삭제 | O(n) | O(1) |
| 뒤 삽입/삭제 | 평균 O(1) | O(1) |
| 중간 삽입/삭제 | O(n) | O(n) |

### 실무 기준 선택

대부분의 경우에는 `ArrayList`를 사용한다.

```java
List<String> list = new ArrayList<>();
```

`ArrayList`는 조회가 빠르고, 메모리 사용량이 상대적으로 적으며, CPU 캐시 효율도 좋다.  
반면 `LinkedList`는 이론상 삽입/삭제에 유리해 보이지만, 실제로는 원하는 위치를 찾는 탐색 비용이 크고 캐시 효율이 좋지 않아 자주 사용되지 않는다.

### 정리

- 조회가 많다 → `ArrayList`
- 일반적인 리스트가 필요하다 → `ArrayList`
- 중간 삽입/삭제가 많다고 무조건 `LinkedList`를 쓰는 것은 아니다.
- 큐처럼 앞/뒤 삽입·삭제가 필요하면 보통 `LinkedList`보다 `ArrayDeque`가 더 적합하다.
- `LinkedList`는 특별한 이유가 있을 때만 사용한다.

> 결론: Java에서 List가 필요하면 대부분 `ArrayList`를 먼저 선택하면 된다.

## 스택(Stack)과 큐(Queue)

스택과 큐는 데이터를 저장하고 꺼내는 자료구조로, 구현 방식은 언어나 환경에 따라 다르지만, 배열이나 연결 리스트를 이용해 구현할 수 있다.

Java로 구현할 때는 보통 `Stack` 클래스보다 `ArrayDeque`를 사용하는 것이 권장된다.

스택은 후입선출(LIFO) 구조로, 가장 나중에 들어온 데이터가 가장 먼저 나간다.

```java
Stack<Integer> stack = new Stack<>();
stack.push(1);
stack.push(2);
System.out.println(stack.pop()); // 2
```

큐는 선입선출(FIFO) 구조로, 가장 먼저 들어온 데이터가 가장 먼저 나간다.

큐도 배열이나 연결 리스트를 이용해 구현할 수 있다.

Java로 구현할 때는 `Queue` 인터페이스와 `ArrayDeque`를 함께 많이 사용한다.

```java
Queue<Integer> queue = new LinkedList<>();
queue.offer(1);
queue.offer(2);
System.out.println(queue.poll()); // 1
```

- 구현은 배열이나 연결 리스트 기반으로 할 수 있다.
- Java에서는 스택과 큐 모두 `ArrayDeque`를 많이 사용한다.

## 우선순위 큐(Priority Queue)

우선순위 큐는 **먼저 들어온 순서가 아니라, 우선순위가 높은 데이터부터 먼저 나가는 자료구조**이다.

일반 큐는 먼저 들어온 데이터가 먼저 나가는 **FIFO(First In First Out)** 구조이다.

```text
입력: A -> B -> C
출력: A -> B -> C
```

하지만 우선순위 큐는 데이터마다 우선순위가 있고, 들어온 순서와 상관없이 우선순위가 높은 데이터가 먼저 나온다.

```text
입력: A(우선순위 3), B(우선순위 1), C(우선순위 2)
출력: B -> C -> A
```

위 예시에서는 숫자가 작을수록 우선순위가 높다고 가정했다.

### 특징

- 데이터의 입력 순서보다 우선순위가 중요하다.
- 가장 우선순위가 높은 데이터를 먼저 꺼낸다.
- 보통 힙(Heap)을 이용해 구현한다.
- 일반 큐처럼 단순한 대기열이 아니라, 중요도 기준으로 처리 순서를 정할 때 사용한다.

### 시간복잡도

| 작업 | 시간복잡도 |
|---|---:|
| 삽입 | O(log n) |
| 최우선 데이터 삭제 | O(log n) |
| 최우선 데이터 확인 | O(1) |

### 사용 사례

- 작업 스케줄링
- 응급실 환자 처리
- 네트워크 패킷 처리
- 운영체제 프로세스 스케줄링
- 다익스트라 최단 경로 알고리즘
- 중요도 기반 알림 처리

### 정리

- 큐는 먼저 들어온 데이터가 먼저 나간다. → `FIFO`
- 우선순위 큐는 우선순위가 높은 데이터가 먼저 나간다.
- 입력 순서보다 처리 우선순위가 중요할 때 사용한다.
- 보통 힙을 이용해 구현한다.
