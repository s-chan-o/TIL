# 심화 개념

## 시간복잡도와 공간복잡도, Big-O 표기법

### 시간복잡도

시간복잡도는 **입력 크기가 커질 때 알고리즘의 실행 시간이 얼마나 증가하는지 나타내는 것**이다.

예를 들어 데이터가 `n`개일 때, 한 번만 확인하면 `O(1)`이고, 모든 데이터를 한 번씩 확인하면 `O(n)`이다.

```text
O(1)  -> 입력 크기와 상관없이 일정
O(n)  -> 입력 크기만큼 증가
O(n²) -> 입력 크기의 제곱만큼 증가
```

### 공간복잡도

공간복잡도는 **입력 크기가 커질 때 알고리즘이 사용하는 메모리가 얼마나 증가하는지 나타내는 것**이다.

예를 들어 변수 하나만 사용하면 `O(1)`이고, 입력 크기만큼 배열을 새로 만들면 `O(n)`이다.

```text
O(1) -> 추가 메모리를 거의 사용하지 않음
O(n) -> 입력 크기만큼 추가 메모리 사용
```

### Big-O 표기법

Big-O 표기법은 **알고리즘의 성능을 입력 크기 기준으로 표현하는 방법**이다.  
정확한 실행 시간이 아니라, 입력이 커질수록 증가하는 정도를 표현한다.

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
```

### 자주 나오는 Big-O

| 표기 | 의미 | 예시 |
|---|---|---|
| O(1) | 입력 크기와 상관없이 일정 | 배열 인덱스 접근 |
| O(log n) | 탐색 범위가 절반씩 줄어듦 | 이진 탐색 |
| O(n) | 입력 크기만큼 반복 | 배열 전체 탐색 |
| O(n log n) | 효율적인 정렬 알고리즘 | 병합 정렬, 퀵 정렬 평균 |
| O(n²) | 이중 반복문 | 버블 정렬, 선택 정렬 |

### 정리

- 시간복잡도는 실행 시간이 얼마나 증가하는지 나타낸다.
- 공간복잡도는 메모리 사용량이 얼마나 증가하는지 나타낸다.
- Big-O는 입력 크기가 커질 때의 성능 증가 추세를 표현한다.
- 보통 알고리즘을 비교할 때는 최악의 경우를 기준으로 Big-O를 많이 사용한다.

## 재귀와 동적 프로그래밍의 관계

재귀는 **함수가 자기 자신을 다시 호출해서 문제를 해결하는 방식**이다.  
큰 문제를 작은 문제로 나누어 풀 때 자주 사용한다.

```text
큰 문제 -> 작은 문제 -> 더 작은 문제
```

동적 프로그래밍(Dynamic Programming, DP)은 **작은 문제의 결과를 저장해두고, 같은 문제가 다시 나오면 재사용하는 방식**이다.

즉, DP는 재귀처럼 문제를 작은 문제로 나눌 수 있지만, 핵심은 **중복 계산을 줄이는 것**이다.

### 관계

재귀는 문제를 푸는 방식이고, DP는 중복되는 재귀 호출을 최적화하는 방법으로 볼 수 있다.

예를 들어 피보나치 수열을 단순 재귀로 풀면 같은 계산이 계속 반복된다.

```text
fib(5)
= fib(4) + fib(3)
= fib(3) + fib(2) + fib(2) + fib(1)
```

여기서 `fib(3)`, `fib(2)` 같은 값이 여러 번 계산된다.  
DP는 이런 값을 한 번 계산한 뒤 저장해서 다시 사용한다.

### DP를 사용할 수 있는 조건

DP는 아무 문제에나 쓰는 것이 아니라, 보통 다음 조건이 있을 때 사용한다.

- **중복 부분 문제**: 같은 작은 문제가 반복해서 등장한다.
- **최적 부분 구조**: 작은 문제의 답을 이용해 큰 문제의 답을 구할 수 있다.

### 정리

- 재귀는 자기 자신을 호출해 문제를 작게 나누는 방식이다.
- DP는 작은 문제의 결과를 저장해 중복 계산을 줄이는 방식이다.
- 모든 재귀가 DP는 아니다.
- 중복되는 계산이 많을 때 재귀에 메모이제이션을 적용하면 DP가 된다.

## LRU 캐시를 구현하는 방법

LRU(Least Recently Used) 캐시는 **가장 오랫동안 사용되지 않은 데이터를 먼저 제거하는 캐시 교체 방식**이다.

캐시의 용량이 가득 찼을 때, 가장 최근에 사용된 데이터는 유지하고 가장 오래 사용되지 않은 데이터를 제거한다.

### 핵심 아이디어

LRU 캐시는 두 가지 작업이 빨라야 한다.

- 데이터를 빠르게 찾기
- 최근 사용 순서를 빠르게 갱신하기

이를 위해 보통 **해시 테이블 + 이중 연결 리스트**를 함께 사용한다.

### 자료구조

| 자료구조 | 역할 |
|---|---|
| 해시 테이블 | key로 노드를 빠르게 찾음 |
| 이중 연결 리스트 | 최근 사용 순서를 관리함 |

해시 테이블은 `key -> node` 형태로 저장한다.  
이중 연결 리스트는 최근에 사용한 데이터를 앞쪽에 두고, 오래 사용하지 않은 데이터를 뒤쪽에 둔다.

```text
최근 사용                    오래됨
head -> A -> B -> C -> tail
```

### 동작 방식

**조회(get)**

```text
1. key가 해시 테이블에 있는지 확인한다.
2. 없으면 캐시 미스이다.
3. 있으면 해당 노드를 리스트의 맨 앞으로 옮긴다.
4. value를 반환한다.
```

**삽입(put)**

```text
1. key가 이미 있으면 value를 갱신하고 맨 앞으로 옮긴다.
2. key가 없으면 새 노드를 맨 앞에 추가한다.
3. 캐시 용량을 넘으면 리스트의 맨 뒤 노드를 제거한다.
4. 제거한 노드는 해시 테이블에서도 삭제한다.
```

### 시간복잡도

| 작업 | 시간복잡도 |
|---|---:|
| get | O(1) |
| put | O(1) |

해시 테이블로 노드를 바로 찾고, 이중 연결 리스트로 노드를 바로 제거하거나 앞으로 옮길 수 있기 때문에 `O(1)`이 가능하다.

### 정리

- LRU 캐시는 가장 오래 사용되지 않은 데이터를 먼저 제거한다.
- 해시 테이블은 빠른 조회를 담당한다.
- 이중 연결 리스트는 최근 사용 순서를 관리한다.

## B-Tree와 B+Tree, 데이터베이스 인덱스와의 관계

### B-Tree

B-Tree는 **하나의 노드가 여러 개의 key와 자식을 가질 수 있는 균형 트리**이다.

일반 이진 탐색 트리는 한 노드가 최대 2개의 자식만 가질 수 있지만, B-Tree는 하나의 노드가 여러 자식을 가질 수 있다.

```text
        [10, 20]
       /   |    \
   [1, 5] [15] [25, 30]
```

B-Tree는 항상 균형을 유지하기 때문에 탐색, 삽입, 삭제가 안정적으로 빠르다.

**특징**

- 하나의 노드에 여러 key를 저장할 수 있다.
- 하나의 노드가 여러 자식을 가질 수 있다.
- 모든 leaf node가 같은 깊이에 있다.
- 트리의 높이가 낮아진다.
- 탐색, 삽입, 삭제가 `O(log n)`이다.

### B+Tree

B+Tree는 B-Tree를 변형한 구조이다.  
가장 큰 차이는 **실제 데이터가 leaf node에만 저장된다는 점**이다.

내부 노드는 탐색을 위한 key만 가지고, 실제 데이터는 leaf node에 저장된다.

```text
          [10, 20]
         /   |    \
      [1,5] [10,15] [20,25,30]
        <------ leaf nodes linked ------>
```

또한 leaf node들이 연결 리스트처럼 연결되어 있어 범위 탐색에 유리하다.

**특징**

- 실제 데이터는 leaf node에만 저장된다.
- 내부 노드는 탐색용 key만 가진다.
- leaf node들이 서로 연결되어 있다.
- 범위 검색에 강하다.
- 데이터베이스 인덱스에서 많이 사용된다.

### B-Tree와 B+Tree 비교

| 구분 | B-Tree | B+Tree |
|---|---|---|
| 데이터 저장 위치 | 내부 노드와 leaf node | leaf node에만 저장 |
| 내부 노드 역할 | key와 데이터 저장 가능 | 탐색용 key만 저장 |
| 범위 탐색 | 상대적으로 불리 | leaf node 연결로 유리 |
| 순차 접근 | 불리 | 유리 |
| DB 인덱스 활용 | 사용 가능 | 더 많이 사용됨 |

### 데이터베이스 인덱스와의 관계

데이터베이스 인덱스는 테이블에서 원하는 데이터를 빠르게 찾기 위한 자료구조이다.

테이블 전체를 처음부터 끝까지 탐색하면 데이터가 많을수록 느려진다.

```text
Full Scan: 모든 row를 확인
Index Scan: 인덱스를 통해 필요한 위치를 빠르게 찾음
```

DB 인덱스에 B-Tree나 B+Tree를 사용하는 이유는 다음과 같다.

- 트리의 높이가 낮아 디스크 접근 횟수를 줄일 수 있다.
- 균형 트리라서 탐색 성능이 안정적이다.
- 정렬된 key를 유지하기 때문에 범위 검색에 유리하다.
- B+Tree는 leaf node가 연결되어 있어 순차 조회와 범위 조회에 특히 강하다.

예를 들어 `age` 컬럼에 인덱스가 있으면 다음 조건을 빠르게 찾을 수 있다.

```sql
WHERE age = 20
WHERE age BETWEEN 20 AND 30
ORDER BY age
```

특히 B+Tree는 `BETWEEN`, `<`, `>`, `ORDER BY`처럼 정렬과 범위가 필요한 쿼리에 강하다.

### 정리

- B-Tree는 여러 key와 여러 자식을 가질 수 있는 균형 트리이다.
- B+Tree는 실제 데이터를 leaf node에만 저장하고 leaf node끼리 연결한다.
- B+Tree는 범위 탐색과 순차 접근에 강하다.
- 데이터베이스 인덱스는 데이터를 빠르게 찾기 위해 B-Tree 또는 B+Tree 구조를 사용한다.
- DB에서는 범위 검색과 디스크 접근 최적화 때문에 B+Tree가 많이 사용된다.
