# 보안 관련

## CORS란

CORS(Cross-Origin Resource Sharing)는 브라우저가 서로 다른 출처(Origin) 간의 요청을 제한하고, 서버가 이를 허용할지 결정할 수 있게 하는 보안 정책이다.

출처(Origin)는 다음 3가지로 구분된다.
- 프로토콜
- 도메인
- 포트

**왜 필요한가**

브라우저는 기본적으로 다른 출처의 리소스에 마음대로 접근하지 못하도록 제한한다. 만약 이런 제한이 없으면, 사용자가 로그인한 사이트의 정보를 악성 사이트가 브라우저를 통해 몰래 읽어갈 수 있다.

**동작 방식**

1. 브라우저가 다른 출처로 요청을 보낼 때 `Origin` 헤더를 함께 보낸다.
2. 서버는 응답 헤더에 `Access-Control-Allow-Origin`을 포함해 허용 여부를 알려준다.
3. 브라우저는 이 값을 확인한 뒤, 허용된 경우에만 응답을 자바스크립트에서 읽을 수 있게 한다.
4. `PUT`, `PATCH`, `DELETE` 같은 요청이나 커스텀 헤더를 사용하는 경우에는 실제 요청 전에 `OPTIONS` 메서드로 Preflight 요청을 먼저 보낸다.
5. 서버가 허용하면 실제 요청을 보내고, 허용하지 않으면 브라우저가 차단한다.

## XSS, CSRF 공격

**XSS**

공격자가 악성 스크립트를 웹 페이지에 주입해 피해자 브라우저에서 실행시키는 공격이다. -> 피해자가 페이지 방문 시 쿠키 탈취

**CSRF**

인증된 사용자 모르게 의도치 않은 요청을 서버에 보내게 유도하는 공격이다.

## SQL Ingection

SQL Injection은 사용자 입력값에 악의적인 SQL 구문을 삽입해 DB를 조작하는 공격이다.

**막는 방법**

1. 'PreparedStatement' 같은 파라미터 바인딩을 사용해 입력값을 SQL 코드가 아닌 데이터로 처리한다.
2. 사용자 입력값을 검증하고, 허용된 형식만 받도록 제한한다.
3. 데이터베이스 게정에 필요한 최소 권한만 부여해 피해 범위를 줄인다.
4. 에러 메시지에 SQL문이나 DB 구조가 노출되지 않도록 한다.
5. 동적 쿼리를 직접 문자열로 이어붙이지 않고, ORM이나 안전한 쿼리 빌더를 사용한다.

## 대칭키 암호화, 비대칭키 암호화

**대칭키 암호화**

암호화와 복호화에 같은 키를 사용하는 방식이다. 속도가 빠르지만, 같은 키를 상대에게 안전하게 전달해야 한다는 문제가 있다.

**비대칭키 암호화**

공개키와 개인키처럼 서로 다른 키를 사용하는 방식이다.공개키로 암호화한 데이터는 개인키로만 복호화할 수 있다. 키 교환과 인증에 유리하지만, 대칭키 암호화보다 속도가 느리다.


실제로는 둘 중 하나만 사용하는 것이 아니라 함께 사용하는 경우가 많음
ex) HTTPS에서는 비대칭키 암호화로 세션 키를 안전하게 교환하고, 이후 실제 데이터 통신은 빠른 대칭키 암호화로 처리

## 인증(Authentication), 인가(Authorization)

**인증**

사용자가 누구인지 확인하는 과정이다. 예를 들어 아이디와 비번을 확인하거나, 토큰을 검증해 로그인한 사용자인지 판단하는 것이 인증이다.

**인가**

인증된 사용자가 특정 자원이나 기능에 접근할 권한이 있는지 확인하는 과정이다. 예를 들어 관리자만 관리자 페이지에 접근할 수 있게 제한하는것이 인가이다.
