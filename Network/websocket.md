## websocket이란

WebSocket은 웹, 앱과 서버 간의 지속적인 연결을 제공하는 프로토콜이다. 이를 통해 서버와 클라이언트 간에 양방향 통신이 가능해진다.

> websocket 과 http의 차이점

**websocket**

```
웹소켓은 실시간 통신이 가능하다

- 연결지향(양방향)

- 한 번 연결 맺은 뒤 유지함

- 헨드쉐이크 과정에서는 헤더의 비중이 크지만, 한번 연결이 되면 간단한 메세지들만 오고감 -> 굉장히 경제적임
```

**http**

```
http로는 실시간 통신이 불가능하다

- 비연결성(단방향)

- 매번 연결 맺고 끊는 과정

- request - response 구조

- 헤더의 비중이 너무 큼 -> 실시간성으로 많은 데이터를 주고 받고자 하는 경우에는 매우 부담이 되는 요소 중 하나임
```

> websocket의 동작

![alt text](image.png)

- 웹소켓은 http 포트 80, https 포트 443위에서 동작한다.

- 웹소켓은 TCP연결 처럼 핸드쉐이크를 이용해 연결을 맺는다. 이때 http 업그레이드 헤더를 사용해서 http 프로토콜에서 웹소켓 프로토콜로 변경한다.

- 최초 접속시에는 http 프로토콜을 이용해 헨드쉐이킹을 한다.

- 이후 연결이 맺어지면 어느 한쪽이 연결을 끊지 않는 이상 영구적인 동일한 채널이 맺어지고, http 프로토콜이 웹소켓 프로토콜로 변경된다.

- 이때 데이터를 암호화하기 위해 WSS 프로토콜 등을 이용할 수도 있다. 

> websocket 프로토콜의 특징

- 최초 접속시에만 http 프로토콜 위에서 헨드쉐이킹 하기 때문에 http 헤더를 사용한다.

- 웹소켓을 위한 별도의 포트는 없고, 기존 포트를 사용한다.

- 프레임으로 구성된 메세지라는 논리적 단위로 송수신 한다.

- 메시지에 포함될 수 있는 교환 가능한 메시지는 텍스트와 바이너리 뿐이다.
