## @Builder

#### 빌더패턴??

보통 객체를 정의하고 그 객체를 생성할 때 보통 생성자를 통해 생성하는 것을 생각한다.
하지만 생성자를 통해 객체를 생성하는데 몇 가지 단점이 있어 객체를 생성하는 별도 Builder를 두는 방법이 있다.

```java
Chicken chicken = Chicken.builder()
                            .name("hello")
                            .money("20000")
                            .brend("bhc")
                            .build();
```

객체를 생성할 수 있는 빌더를 builder() 함수를 통해 얻고 거기에 셋팅하고자 하는 값을 세팅하고 하는 값을 셋팅하고 마지막에 builder()를 통해 빌더를 작동 시켜 객체를 생성한다.

> 빌더를 써야하는 이유

1. **생성자 파라미터가 많을 경우 가독성이 좋지 않다.**

위 예시에서 Chicken 클래스는 생성자 파라미터를 3개만 받는다. 이정도까진 괜찮다. 하지만 생성자 파라미터로 받아야하는 값이 많아진다면 각 값들이 어떤 값을 의미하는지 이해하기 힘들 것이다.

하지만 이를 빌더 패턴으로 구현하면 각 값들은 빌더의 각 값들의 이름 함수로 셋팅이 되어 각각 무슨 값을 의미하는지 파악하기 쉽다.

따라서 생성자로 설정해야하는 값이 많을 경우 빌더를 쓰는 것이 생성자보다 가독성이 좋다.

2. **어떤 값을 먼저 설정하던 상관 없다.**

생성자의 경우는 정해진 파라미터 순서대로 꼭 값을 넣어줘야하지만 빌더 패턴은 빌더의 필드 이름으로 값을 설정하기 때문에 순서에 종속적이지 않다.

그냥 쓰이는 곳에서 어떤 필드를 먼저 설정해야하는지 굳이 순서를 생각할 필요 없이 편하게 설정하면 된다.

```java
Chicken chicken = Chicken.builder()
                            .name("hello")
                            .brend("bhc")// brend를 money 먼저
                            .money("20000")
                            .build();
```

---

#### @Builder

위와 같은 이유로 생성자 대신 빌더를 사용하는데 빌더는 그렇다면 어떻게 구현해야하나??

우선 코드로 빌더를 만들고 그 안에서 멤버 필드별로 값을 설정하고 빌더를 반환하는 함수를 만들면 된다. 하지만 이 방법은 멤버 필드 별로 함수를 생성해야하는 등 생성자보다 더 번거롭고 해당 클래스에 들어갔을 때 빌더로만 몇십줄을 차지해서 코드 읽기도 불편하다. 그래서 나온것이 @Builder 어노테이션이다.

사용법은 아주 간단하다. 빌더 패턴을 적용할 객체에 @Builder 어노테이션을 달기만 하면 된다.

```java
@Builder
public class Chicken{
    private String name;
    private int money;
    private String brend;
}
```

어노테이션만 달면 빌더가 생기고 위에 썼던 것과 같이 빌더를 통해 객체를 생성할 수 있다.
