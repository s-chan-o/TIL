## 제어의 역전(IoC)

> 제어의 역전(IoC)이란?

IoC는 Inversion of Control의 약자로 영문 직역 자체가 "제어의 역전" 이다.

``제어의 역전은 기존의 개발 방식에서 개발자가 직접 흐름을 제어하는 것이 아니라, 외부의 프레임워크나 라이브러리가 제어 흐름을 대신하게 되는 것을 말한다.``

> IoC의 구현방법

- Factory Pattern

객체 생성을 전담하는 팩토리 클래스를 두어 객체를 생성하는 방식

- Template Method Pattern

객체 생성 과정을 추상화하여, 하위 클래스에서 구체적인 구현을 담당하는 방식

- Service Locator Pattern

객체 생성 및 관리를 위한 서비스 위치자 패턴

- Dependency Injection (DI)

객체 생성 및 관리에 대한 책임을 IoC 컨테이너가 가지며, 필요한 객체를 직접 생성하거나 외부에서 주입받는 방식

> 장단점

**장점 :**

- 코드의 유연성, 재사용성 증가

- 테스트의 용이성 증가

- 결합도가 낮아져 유지보수가 용이해짐

- 객체간, 의존성 관리를 통해 개발 시간을 단축시킬 수 있다.

**단점 :**

- 의존성 주입이 많아질수록 코드의 가독성이 떨어질 수 있음

- 코드의 복잡성 증가

- IoC 컨테이너가 복잡해질수록 초기 설정과 성능 이슈 발생
